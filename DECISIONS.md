# Architectural & Production Decisions (`DECISIONS.md`)

Records confirmed constraints from the specifications alongside reversible engineering choices and environment adaptations.

---

## 1. Locked Platform, Phasing & Gameplay Rules (Authority: User Direction + Handoff §1–§3)

- **Two-Phase Delivery Plan (Explicit User Override — Decision Precedence #1):**
  - **Phase 1 (*Dig Dug* 1982 MVS Replica):** Disassemble the original 1982 *Dig Dug* arcade Z80 ROMs to build a faithful 68000 Neo Geo MVS replica with authentic speeds, pump timings, monster AI/ghosting, rock delays, round tunnel layouts, bonus fruit tables, and scoring—rendered with updated Neo Geo graphics.
  - **Phase 2 (*Super Dig Dug* Expansion):** Expand the verified Phase 1 MVS engine with the 48 curated additions (`01`–`48`).
- **Screen Layout (Explicit User Choice):** **Horizontal `320×224` with Side-Panel HUD + Adapted Height** — single-screen landscape presentation placing `1UP / HIGH SCORE / Lives / Round Flowers` in a side HUD column and adapting vertical underground strata height to fit cleanly within `224` px (no camera scrolling, no TATE rotation).
- **Target Hardware:** Standard SNK Neo Geo MVS (`320×224`, 12 MHz 68000, Z80 + YM2610, 64 KiB Work RAM, 96 sprite strips/scanline hardware max, 80 strips/scanline working ceiling).
- **Controls & Loadout:** 4-way movement/digging, Button `A` = unlimited pump (plus 1 pre-zone pump module in Phase 2), Button `B` = finite-ammo special in Phase 2. No in-combat inventory switching.
- **Universal Solvability:** Every normal enemy and boss encounter must remain completable using movement, digging, standard pumping, and rocks after special ammo is exhausted.

## 2. Reversible Working Defaults

| ID | Area | Decision / Working Default | Rationale & Reversibility |
|---|---|---|---|
| **D-01** | Side-HUD Horizontal Arena Geometry | On `320×224`: `224×224` left/center playfield (`14×14` visual `16×16` tiles = `28×28` logical `8×8` occupancy cells, matching original *Dig Dug*'s exact `224` px / `14`-column width!) + `96×224` right-hand FIX HUD panel (`x=224..319`, `12` FIX columns wide). | Preserves 1982 *Dig Dug*'s **exact 14-column (`224` px) horizontal tunnel geometry** 1:1 while fitting `224` px height cleanly (`14` rows instead of `16`, using only **14 vertical sprite strips** for dirt!) and leaving a crisp `96` px arcade side panel for scores, lives, flowers, and Phase 2 loadout icons. |
| **D-02** | Fixed-Point Coordinates | World positions use signed `Q12.4` (`1/16` pixel subpixel precision, `int16_t`) relative to screen top-left. | Fits cleanly in 16-bit 68000 registers without overflow across `320×224`, supports smooth tunnel vs. dig speeds, and serializes identically on host and 68000. |
| **D-03** | Frame Timing & Authoring Ticks | Simulation runs at 1 tick per VBlank (`~59.1921 Hz` MVS NTSC, `~16.894 ms/tick`). Offline animation converter maps milliseconds to integer ticks via `max(1, round(ms * 59.1921 / 1000.0))`. | Satisfies Handoff §6 and Sprite Guide §2B ("do not assume exactly 60 Hz"). |
| **D-04** | Shared Terrain Mask Contract | Each `16×16` visual tile encodes filled `8×8` quadrants as `bit0=TL`, `bit1=TR`, `bit2=BL`, `bit3=BR` (`0`=empty tunnel, `15`=solid earth). Generated into a single shared header/module consumed by both Python asset tools and C runtime. | Eliminates any drift between collision occupancy and visual dirt tiles (Sprite Guide §3). |
| **D-05** | Same-Frame Precedence | Within a frame: (1) terrain edits & rock support checks, (2) rock crush / blast / projectile hits, (3) pump pop resolution. First lethal cause in priority order commits death and awards score once (with combined technique flags attached prior to commit). Simultaneous last-enemy death and player death resolves player death first (stage does not clear if no live player remains). | Explicit deterministic rule required by Handoff §6; covered by host unit tests. |
| **D-06** | Editable Pixel Master Fallback | Because `aseprite` is not installed in the current build container, canonical editable masters are stored as deterministic Python pixel-construction scripts + native indexed PNG sheets + JSON metadata (`canvas`, `pivot`, `hitbox`, `duration_ticks`, `sockets`, `animations`). No fake `.aseprite` files are created. | Explicitly permitted and prescribed by Sprite Guide §2A. |
| **D-07** | Zero-Dependency PNG & Bitplane Tooling | Asset scripts in `tools/assets/` use Python 3.12 standard library (`zlib`, `struct`, `json`) + `numpy` to read/write exact `PLTE`/`tRNS` 4bpp/8bpp indexed PNGs and encode/decode Neo Geo C-ROM (`C1`/`C2`) and S-ROM (`S1`) tiles without requiring Pillow or external network installs. | Keeps the asset pipeline 100% deterministic, self-contained, and runnable inside air-gapped containers. |
| **D-08** | Neo Geo Palette Word Conversion | Editable RGB888 colors convert to 16-bit Neo Geo palette RAM words (`bit15` dark bit, `bits14..12` R0/G0/B0 LSBs, `bits11..8` R4..R1, `bits7..4` G4..G1, `bits3..0` B4..B1) via a dedicated tested encoder/decoder in `tools/assets/`. | Prevents assuming standard packed RGB555 order (Sprite Guide §4). |
| **D-09** | Missing Concept PNG Handling | `Armored Mecha-Pooka pixel sprite.png` and `Pixel Air Cannon Pickup.png` are not yet present in `assets/concepts/`. Initial `enm_mecha_pooka` and `tool_air_cannon` pixel masters follow the written visual briefs; user review will confirm or supply the PNGs if closer visual matching is desired. | Follows Sprite Guide §1 ("If those images are absent, use the written art briefs and simple pixel placeholders... Do not claim to have inspected an unavailable image"). |
| **D-10** | Build Orchestration | Top-level `Makefile` delegates to `python3 tools/sdd.py <subcommand>` so workstations with GNU Make can run `make <target>` while minimal containers without `make` run `python3 tools/sdd.py <target>`. | Bridges sandbox constraints (`make` absent) with requested project interface (`make assets`, `make rom`, etc.). |
| **D-11** | Dual-Mode 150 MB User Asset Pack Compiler | `assets/pack_catalog.jsonl` (`65` families, `2,074` frames, `335` clips) + `assets/audio_catalog.json` (`53` WAVs) are committed in Git; `tools/assets/pack_pipeline.py` ingests `Super-Dig-Dug-Complete-Asset-Pack.zip` directly on the user's Mac (`make assets PACK=...`) while synthesizing deterministic stand-ins with **identical** C symbols, tile counts (`8,203` C-ROM tiles, `512` S-ROM tiles), and V-ROM cue indices (`51`) in CI. | Overcomes cloud chat upload limits for 150 MB binary archives with zero manual conversion on the user's machine. |
| **D-12** | Multi-Palette Scene Partitioning | Full-screen `>15`-color art families (`ui_world_cards`, `ui_ending`) are partitioned per `16×16` tile across dedicated 12-slot sub-palette ranges (`96..107` and `108..119`), preserving crisp colors within Neo Geo's 15-visible-color/tile limit. | Avoids muddying multi-biome world cards down to a single 15-color palette. |
| **D-13** | Sample-Locked 3-Stem YM2610 ADPCM-A Driver | `tools/build_m1_z80.py` + `src/audio/z80_driver.asm` build a 128 KB Z80 M1 ROM (`build/m1.bin`) without requiring patched SDCC. Channels `0..2` key-on together (`Port B $00 = $07`) for `01_burrow_groove`, `02_motion_melody`, and `03_danger_percussion`, re-triggering on Status 1 (`in a, ($06)`) bit 0 and muting/unmuting via `$08..$0A` (`$DF` vs `$00`), while channels `3..5` play SFX/stingers round-robin. | Honors `__music__.mix_behavior` ("Start all three stems at the same sample. Keep groove active, add melody while moving, add percussion in danger") in pure YM2610 hardware. |
| **D-14** | MVS Interrupt Vector & P1 Endianness | `crt0_mvs.S` binds LSPC2 VBlank to Level 1 Autovector (`$000064`), Timer to Level 2 (`$000068`), includes the mandatory `$000182` SNK security recognition stub, and `neogeo_rom_builder.py` pads `p1` to `512 KiB` and byte-swaps 16-bit pairs (`load16_word_swap`), accepting either `ngdevkit` (`m68k-neogeo-elf-gcc`) or Homebrew `m68k-elf-gcc`. | Prevents blank-screen vector mismatch on retail MVS BIOS (`sp-s2.sp1`) and makes macOS compilation effortless. |
| **D-15** | Toolchain and BIOS for verification | Build with ngdevkit from `ppa:dciabrin/ngdevkit` (`m68k-neogeo-elf-gcc` 15.3, `z80-neogeo-ihx-sdasz80`); verify in MAME 0.264 with ngdevkit **nullbios** as `mame/roms/neogeo.zip`. `tools/setup_linux.sh` installs everything. Supersedes the Homebrew/MacPorts `m68k-elf-gcc` route of D-14, which failed on macOS 12. | Matches the handoff's recommended SDK, gives a 68000-correct libgcc, and needs no commercial BIOS. Other `m68k-*-gcc` prefixes are still probed by the ROM builder. |
| **D-16** | MAME loading route | Cartridges load through a project software list: `mame neogeo <cart> -hashpath mame/hash -rompath mame/roms`. Each build writes `mame/hash/<cart>.entry` and regenerates `neogeo.xml` from all entries. | Proven in MAME; no donor game identity and no MAME source patch. |
| **D-17** | BIOS credit/start contract | Coins and credits belong to the BIOS: the VBlank handler calls `SYSTEM_IO`, credits are read from backup RAM (`$D00034`), and a start arrives through `PLAYER_START` with `BIOS_START_FLAG`; the game sets `BIOS_USER_MODE` to 2 in play and 1 on the title. A coin outside play makes the BIOS restart `USER` with request 3, which re-runs the C runtime. | Required on MVS; replaces the private credit counter. Consequence: the RAM high-score table is reset by a coin on the title until it moves to the backup-RAM block (`$10E000`). |
| **D-18** | Persistent terrain layer | Hardware sprites 1..14 are a persistent background layer; the world sets `dirty_cols` and only those columns are rewritten. Dynamic strips start at sprite 15. Strip telemetry is opt-in. | Cut the tick from ~3 frames to under 1 (measured in MAME). |
| **D-19** | Z80 driver as assembly source | `src/audio/z80_driver.s` (sdasz80) replaces the hand-emitted byte stream of D-13; `z80_driver.bin` is committed so the ROM builds without a Z80 assembler. The 68000 releases one queued sound command per VBlank and sends `$03` at init. | The old emitter never enabled NMI and clobbered registers. Back-to-back writes to `REG_SOUND` overwrite the command latch. |
| **D-20** | ADPCM-A codec | Encoder and reference decoder follow the YM2610 as emulated by MAME: step adjust `{-1,-1,-1,-1,2,5,7,9}`, delta `(2n+1)*step/8`, wrapping 12-bit accumulator. | The previous OKI-style tables decoded to saturated noise on the chip. |
| **D-21** | Asset pack location | The art/audio pack is fetched from the owner's Google Drive (`digdug/Super-Dig-Dug-Art`) into `Super-Dig-Dug-Art/` at the repository root (git-ignored). Only `atlas.png`, `atlas.json`, `palette.json` per family and the WAVs are needed (about 7 MB). | Keeps third-party-sized binaries out of git unless the owner decides otherwise. |
| **D-22** | Vertical adaptation of the 1982 field | The original has 15 dirt rows (strata 4/4/4/3); 224 px leaves room for 13. Its 15 round layouts only use rows 4..15, so the port keeps original rows 3..15 (port row = original − 2): strata 3/4/4/2, all tunnel, monster and rock positions unchanged relative to each other. Supersedes the 3/4/3/3 strata and invented layouts. | Loses one empty row above the highest tunnels and the empty bottom row; nothing a layout places is moved. Alternative (drop the two top rows, strata 2/4/4/3) is a one-constant change in `tools/extract_dd1982_tables.py`. |
| **D-23** | Movement model from the ROM | Player and monsters move in 2-pixel steps gated by 8-bit accumulators with the original rates; Pookas and Fygars update on alternate frames; speeds come from the ROM tables (difficulty bank 0). Port-side assumptions: fast tier = last monster fleeing, mid tier = hurry-up; ghost drift = 1 px per step. | The previous constants were roughly twice the original's speeds. The tier mapping and ghost speed need confirmation against a running original. |
